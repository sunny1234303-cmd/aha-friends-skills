# Phase 2 결과 리포트 포맷

## 상단: Executive Summary

스크롤 없이 결론만 봐도 되도록 맨 위에 배치한다.

```markdown
## 종합 요약 (조사일: YYYY-MM-DD)

### 1순위 — 판정이 가장 흔들리지 않은 후보
- **[회사명]** — PASS. [핵심 근거 1~2줄]

### 조건부 후보 (WATCH) — 재확인 후 지원 가치 있음
- **[회사명]** — [구조는 맞지만 무엇이 미확인인지]

### 하향 / 보류 — 이전엔 유망했으나 재조사로 격하
- **[회사명]** — ⚠️ [최초 판정이 무엇이었고, 왜 뒤집혔는지. 삭제하지 말고 정정 이력으로 남긴다]

### 탈락 확정
- [회사명](사유), [회사명](사유), ...

### 검증 불가 영역 (전 후보 공통)
- [사무공간/회의방식/피드백스타일 등 — 커피챗·면접에서 직접 확인 필요]
```

## 하단: 상세 근거

Phase 1에서 조사한 축별로 표를 나눈다. 표 컬럼은 최소 다음을 포함:

```markdown
| 기업 | 판정 | 근거 (출처 URL 포함) |
|---|---|---|
| [회사명] | PASS/WATCH/UNCLEAR/FAIL | [구체적 근거 문장 + (출처: url)] |
```

카테고리/세그먼트가 여러 개면 섹션을 나눠서 반복한다. 신생·투자유치 기업을 별도로 조사했다면 별도 섹션으로 분리한다(전통 기업과 판단 기준이 다르므로 — 예: 소규모 스타트업은 "직무 미분리" 리스크를 기본 전제로 깔고 본다).

## 정정 이력 표기 규칙

이전 라운드 판정이 재조사로 뒤집히면:

```markdown
| ~~회사명~~ | 이전: PASS → **정정: WATCH/FAIL** | 정정 사유: [무엇을 잘못 판단했는지 구체적으로] |
```

취소선 + 정정 사유를 남겨서, 사용자가 "왜 순위가 바뀌었는지" 이전 대화를 다시 스크롤하지 않아도 이 문서 하나로 파악할 수 있게 한다.
