# n8n 워크플로우 빌더 스킬

## ⚠️ 전제조건 (최초 1회)

이 스킬은 `n8n-mcp` MCP 서버가 연동되어 있어야 동작한다.

1. 로컬 n8n 실행 중인지 확인 (기본: `http://localhost:5678`)
2. n8n 웹 UI → **Settings → n8n API → Create an API key**
3. 발급받은 키를 이 스킬 폴더의 `.env`에 채워넣기 (`.env`는 gitignore 처리해서 저장소에 커밋하지 않는다):
   ```
   # .claude/skills/n8n-workflow-builder/.env
   N8N_API_URL=http://localhost:5678
   N8N_API_KEY=발급받은키
   ```
4. `.mcp.json`의 `${N8N_API_URL}`/`${N8N_API_KEY}` 확장은 **셸 프로세스 환경변수**에서만 값을 읽는다 (Claude Code가 `.env` 파일을 자동으로 읽어주지 않음) — 그래서 `~/.zshrc`(또는 `~/.bashrc`)에 이 `.env`를 소싱하는 한 줄을 추가해야 한다:
   ```
   set -a; source <프로젝트 경로>/.claude/skills/n8n-workflow-builder/.env; set +a
   ```
5. `source ~/.zshrc` 또는 새 터미널에서 Claude Code 재시작 → 처음 이 스킬을 쓸 때 `n8n` MCP 서버 연결 승인 프롬프트가 뜨면 승인

이 스킬 폴더나 프로젝트 저장소 어디에도 API 키를 **하드코딩(코드/문서에 직접 기입)**하지 않는다 — 항상 이 `.env` 파일에서만 읽는다.

## ⚠️ 비용·보안 게이트 — 무조건 최우선

**비용 과금 여부와 보안 문제는 템플릿 적합도·편의성·속도 등 다른 어떤 기준보다 먼저, 무조건 확인한다.** 여러 판단 기준 중 하나가 아니라 통과해야만 다음 단계로 넘어갈 수 있는 게이트다 — 둘 중 하나라도 걸리면 사용자 확인 없이는 절대 진행하지 않는다.

### 비용 게이트
- **선호**: n8n 코어 노드(Cron, HTTP Request, Set, IF, Code, Merge), 무료 티어가 넉넉한 서비스(Google Sheets/Gmail, Slack, Discord, Telegram, RSS, Notion, 공개 무료 API)
- **주의**: 사용량 기반 과금 API(OpenAI/Anthropic 등 LLM API, 유료 SMS(Twilio), 유료 SEO 툴 API, 유료 크롤링/프록시 서비스) — 후보 제시 시 "이 단계는 비용이 발생합니다"라고 반드시 명시
- 같은 목적을 무료로 달성할 대안(예: 유료 크롤링 API 대신 HTTP Request + Code 노드)이 있으면 그쪽을 먼저 제안
- 유료 API가 꼭 필요하면 **배포 전 사용자 확인 없이는 그 노드를 포함한 워크플로우를 만들지 않는다**

### 보안 게이트
아래 항목을 매 후보·매 배포 직전 명시적으로 확인. 문제가 있으면 후보 제외하거나 사용자에게 위험을 알리고 확인받기 전엔 배포하지 않는다.
- **자격증명 노출**: API 키·토큰이 노드 파라미터에 평문으로 박히지 않는가 — 반드시 n8n Credential 참조로만
- **Webhook 노출**: 인증 없이 공개되는 Webhook 트리거가 없는가 (최소 헤더/토큰 검증)
- **Code 노드 인젝션**: 사용자 입력을 검증 없이 실행/쿼리에 그대로 꽂는 패턴이 없는가
- **데이터 유출**: 개인정보·사내 데이터가 불필요하게 제3자 외부 엔드포인트로 나가지 않는가
- **과도한 OAuth 스코프**: 실제 필요한 범위보다 넓게 요청하지 않는가
- **출처 불명 커스텀 노드**: 검증 안 된 커뮤니티 노드는 쓰기 전 사용자에게 알리고 확인

## 안전장치 — 반드시 지킬 것

- **워크플로우는 항상 비활성(inactive) 상태로 생성한다.** 실제 트리거 작동(활성화)은 사용자가 n8n UI에서 직접 검토 후 켠다.
- **자격증명(OAuth 토큰, API 키 등)을 대신 입력하지 않는다.** 노드에 자격증명 슬롯만 만들고, 실제 연결은 사용자 몫.
- **`n8n_delete_workflow`, 활성 워크플로우 수정은 사용자 확인 후에만** 실행한다.

## 진행 순서

1. **요구사항 파악**: 사용자가 말한 자동화를 트리거/조건/액션으로 분해 (예: "매일 아침 9시에 네이버 키워드 순위 체크해서 슬랙으로 알림" → 트리거: Cron 9AM / 액션: HTTP 요청 + Slack 노드)
2. **템플릿 검색**: `search_templates`로 관련 템플릿 검색.
3. **[게이트]** 각 후보에 비용·보안 게이트 적용 → 상위 2~3개를 이름+설명+**무료/유료 여부+보안 이슈 여부**와 함께 제시하고 선택받는다.
4. **템플릿 없으면 처음부터 조립**: 적합한 템플릿이 없으면 `search_nodes`/`get_node`로 필요한 노드 스펙을 조회해 워크플로우 JSON을 직접 구성한다 (이때도 비용·보안 게이트 동일 적용).
5. **커스터마이징**: `get_template`으로 가져온 JSON을 사용자 요구에 맞게 노드 파라미터 수정. 자격증명 필드는 이름만 채우고 실제 값은 비워둔다.
6. **검증**: `validate_workflow`로 전체 검증. 노드 단위 이슈는 `validate_node`로 재확인. 에러 있으면 5번으로 돌아간다.
7. **[게이트]** 배포 직전 최종 확인: 유료 API 노드 있으면 사용자 확인 / 보안 게이트 6항목 재점검 → 하나라도 걸리면 배포 중단하고 보고
8. **배포**: `n8n_create_workflow`로 생성 (비활성 상태 유지).
9. **보고**: 생성된 워크플로우 이름/URL, 남은 수동 작업(자격증명 연결, 활성화)을 사용자에게 안내.

## 결과물

- n8n 인스턴스에 실제로 생성된 워크플로우 (비활성 상태)
- 사용자가 확인해야 할 남은 수동 단계 목록 (자격증명 연결 등)

## 노드 조립 시 흔한 함정 (실전에서 발견)

`validate_workflow`는 구조/문법만 검증하고 이 함정들은 못 잡는다. 검증 통과해도 실제 실행(`n8n_test_workflow` 또는 UI 수동 실행)으로 한 번은 확인할 것.

- **"검색 결과 0건" 분기 처리**: Airtable/DB Search 노드가 0건일 때 다음 노드(IF 등)가 아예 실행되지 않는다. 이후 로직이 0건도 처리해야 하면 **Search 노드 자체**에 `alwaysOutputData: true`를 켜서 빈 아이템이라도 흘려보내야 한다 (다음 노드인 IF에 켜는 게 아님 — IF는 입력이 0개면 그 자체가 실행 안 됨).
- **위 방식으로 만든 빈 아이템을 IF의 "exists"/"notEmpty" 연산자로 판단하면 true/false 양쪽 분기가 동시에 실행되는 버그가 있다.** Search 노드 바로 뒤에 Code 노드를 끼워 `!!$json.id` 같은 명시적 boolean으로 변환하고, IF는 그 boolean 필드만 보게 구성해야 안전하다.
- **Airtable 노드(v2.2) 결과 필드는 `$json.필드명`이 아니라 `$json.fields.필드명`으로 감싸져 있다** (`id`/`createdTime`만 최상위). 다른 서비스 노드도 응답 구조가 이런 식으로 감싸져 있는 경우가 흔하니 실제 실행 로그로 구조를 확인하고 표현식을 쓸 것.
- **노드를 여러 개 거치면 `$json`은 매번 직전 노드의 출력으로 바뀐다.** 중간에 지나가는 노드(이메일 발송 등)가 원본 필드를 그대로 흘려보낸다는 보장이 없으므로, 여러 단계 앞선 노드의 값이 필요하면 `$json` 대신 `$('노드이름').item.json.필드명`으로 명시적으로 참조해야 조용히 깨지지 않는다.
